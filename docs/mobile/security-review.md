# Mobile security and dependency review

Status: release review incomplete. No high-severity exception is approved by this document. See [acceptance verdict](production-acceptance.md). Native clients remain untrusted; hiding privileged screens is not authorization.

## Verified controls

The native transport sends opaque CUSTOMER credentials only to an explicit customer endpoint allowlist. The backend independently restricts native bearer routes and customer/resource ownership. Cookie website sessions/CSRF/origin controls are preserved. SecureStore holds credentials, process-local pending actions are one-use/owner-bound, private query caches clear on account changes, unsafe mutations do not automatically retry, and session expiry/revocation remain server controlled. Tests cover support/saved/enquiry isolation and customer access denial to dealer/admin/workspace/invitation interfaces.

F107 adds fresh-OTP recency, explicit reactivation, shared-role isolation and transaction-serialized deactivation/withdrawal. It never deletes shared Users or reverses append-only evidence. Policy acknowledgment remains separate from dealership sharing. Production drafts/native feature activation stay gated. Secrets remain in the backend: no MSG91, Google secret, database key or session-signing key is part of public native configuration.

Incoming links are origin/path/query bounded, reject credential/privileged destinations and never authorize mutations. Canonical query encoding avoids handing malformed percent-encoding onward. Android App Links association still needs the owner's actual package and Play certificate. Root exception recovery never displays raw errors. No new tracking/crash/notification SDK or broad permission is added. CI validates final merged release permission/debug/backup/cleartext settings and ELF/ZIP alignment; unexecuted device/certificate checks remain separate.

Source-map scan at the SDK-57 patch checkpoint inspects 1,673 sources and finds no Prisma, apps/api, apps/web, broad contracts/legal archives, node-forge, braces, deepmerge-ts, mysql2 or sprintf-js modules. `check-bundle.mjs` repeats the server/archive/build-tool boundary check on Android exports. This is not proof of all native libraries, a credential scan, an API-image assessment or immunity to vulnerabilities. Native/third-party binary behavior and signed artifact review remain launch gates. Audit metadata's dev/runtime labels alone are not sufficient to establish reachability.

Do not lower the existing CI critical gate or mark residual high findings accepted. Do not force ESM/major dependency changes merely to turn an audit green. Engineering/security owner must resolve or explicitly review actual risk before launch. Record advisory versions/date and rerun the audit before release; a future upstream fix can change this assessment.

## Remaining manual security gates

Inspect the exact signed AAB/APK for secrets, debug/cleartext/exported components and unnecessary permissions; verify SecureStore/backup/reinstall behavior on devices, intent parsing/callback isolation and no credentials in logs/analytics. Test actual Android requests against HTTPS/staging, replay/rate limits and expired/revoked sessions. Execute multi-customer/multi-role installed acceptance. Review screenshots/recent-app exposure of support/private data and approved privacy requirements. No arbitrary FLAG_SECURE restriction or new device permission is introduced without a product/privacy decision. Account deletion fulfilment and processor/retention approval remain independently blocking.
