# Dealers-Drive Android: audit and remediation approval plan

Historical audit prepared 16 October 2026; the owner subsequently explicitly approved this plan. Implementation status is tracked separately in README.md. No repository files, protected branches, PRs, backend configuration, policy documents, deployments or store releases were changed. The deliverables and diagnostic probes are outside the repository in `/private/tmp`.

**Recommendation: NO-GO for Android UI/UX launch readiness.** The application has useful functional foundations, but discovery, location, navigation, empty states and lifecycle behavior need coordinated remediation. Overall production, legal and Play Store readiness are separate NO-GO assessments; this campaign cannot approve those releases.

1. **Navigation/header.** Five labeled tabs: Home, Cars, Dealers, Saved, Profile. Public `/cars` and `/dealers` continue to resolve to their tab roots. Root details push above the tab navigator and preserve its state. Hide legacy Explore as a redirect, never as a sixth visible tab. Standard header arrow for pushed pages; close icon for dismissible modals. Use safe-area insets once per surface and verify edge-to-edge status/navigation bars.
2. **Brand.** Reuse the exact PR #311 symbol and separate wordmark assets already installed. White header with near-black artwork and compact district pill; one accessible brand label. At narrow widths or large fonts, allow the location row to sit beneath the lockup rather than squeeze or distort it. Detail headers use contextual title/actions without repeated logo text.
3. **Tokens.** Keep Manrope, near-black `#171716` text, white surfaces and existing warm neutral background/dividers. Strong 32–36sp Home headline, 24–28sp screen titles, 20–22sp sections, 15–16sp body, 13sp secondary text, with font scaling enabled. Use 4/8/12/16/24/32 spacing, 12–16dp surface radii and restrained borders/shadow. Target at least 48dp interactive areas. Error color remains available for actual validation; saved hearts use black only.
4. **Home.** Compact dark photographic hero with the approved existing hero/config artwork, short headline/supporting sentence and search. An Explore Cars action is generic discovery, independent of unselected text; Dealers is a quieter useful link. Recently added and nonempty discovery categories follow promptly. A compact truthful trust block replaces repeated long prose. Never fabricate stock/counts/photographs. Empty scoped market: “No cars available in this district” with Change district and Browse dealers. All districts empty: purposeful marketplace message and dealer discovery. Failed reads are retryable errors, not empty inventory.
5. **Autocomplete.** Search icon, clear control, bounded anchored panel matching field width, light surface, subtle border/elevation. Show API `label` and `metaLabel`, emphasize matching substrings without changing accessible names. Debounce around 300–350ms, immediately hide mismatched responses, cancel obsolete requests and scope by district/towns. Display loading/no matches/error/retry inside the panel. Selecting is the only search-commit action; IME Done dismisses without applying text. Outside tap/Back dismisses; first tap on a result with keyboard open selects it once.
6. **Canonical search.** Current API kinds are BRAND, MODEL and VARIANT only. Brand sets `brand`; model sets `brand+model`; variant adds its literal `q`. Preserve applicable location/nonconflicting filters and clear dependent invalid filters/page. No individual-car or category destination is invented. If the contract later gains a vehicle destination, that requires a separate typed mapping review.
7. **Location.** Shared district pill supports All districts and API-derived districts. No GPS permission or personal location collection. Persist only the chosen public district slug. Cars town filters use matching response facets; selected towns remain removable chips. Dealers shows matching response towns as multi-select pills with counts only where supplied. District change clears dependent town/dealer filters and page; unrelated car preferences remain useful. No stale options from the prior district.
8. **Sort/Filters.** Separate adjacent actions. Sort dialog uses the exact `VehicleSort` options/labels and radio selection, then closes. Filters groups facets/ranges, shows a local draft, Reset and a stable Apply/Show results footer. Numeric ranges retain existing validation and paise conversion. Count appears only for the current successful preview. Back closes/discards this temporary filter draft; applying updates canonical route state once.
9. **Cards/details.** Extend existing `CarCard`: consistent roughly 1.6:1 imagery, fixed dimensions, calm placeholder, year/status badges, black SVG saved heart, title, price, server metadata and dealer strip. Horizontal Home and full-width lists share visual tokens; use variants only for placement. Preserve current availability restrictions and backend labels. Card Save and dealer controls remain separate touch targets. Gallery opens full screen, supports Back/swipe/close and returns to the same detail/list context.
10. **Account/journeys.** Profile becomes grouped navigation rows. Empty Saved/enquiries/support screens explain the state with one useful recovery action. Support issue selector uses shared contract labels. Login prioritizes phone/OTP action, offers quiet resend/change-number controls and a header close. Dirty support/enquiry/deletion drafts receive discard confirmation only when meaningful work would be lost.
11. **Consent.** Keep separate unticked Terms acceptance and Privacy acknowledgment required by the existing native flow. Put a tappable authoritative policy link beside/within each short sentence as an independent accessible target. Sharing wording identifies the actual dealership and name, verified mobile and submitted messages; retain explicit affirmative choice, scope/version checks and the full notice/withdrawal limitation screen. Do not change publication flags, collection rules, evidence payloads, legal text/hashes or withdrawal effects. Current short Terms/Privacy labels need link/layout improvement, not a wholesale copy rewrite.

**C. State ownership and proposed migration**

```text
Validated public/deep-link input
              |
              v
Navigation coordinator ------> Canonical Cars / Dealers route filters
       |                                  |
       | explicit district choice         | normalized query key
       v                                  v
Zustand district preference          TanStack Query
  public slug + hydration flag        public results / facets / locations
  no remote records                   owner-scoped private data
       |                              optimistic saved reconciliation
       v
Non-sensitive local preference storage

Local component state: search text, open panel, filter draft, form fields
SecureStore: session credentials only
SessionManager: verified identity, generations, restore/logout, pending actions
```

| -------------------------------------- | ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |

| Scroll/navigation context              | Mounted tab/detail navigation state       | Add minimal ephemeral offsets keyed by route/filter signature only if measurements show remount loss. No persistent browse history required.                                                                             |

| Enquiry/support/consent/account data   | Owner-scoped TanStack Query               | Keep current API validation/idempotency/version checks. Never persist private queries offline. Local dirty form state clears on actual identity loss/change.                                                             |
| Panels/selection fields                | Local state/shared lightweight primitives | Do not globalize unrelated modal state. Zustand expands only if a demonstrated cross-screen presentation requirement appears.                                                                                            |

The route district is the authoritative scope for an opened directory; the stored slug is a preference used to initialize ordinary discovery. A validated external route initializes that context explicitly, including an all-districts route. A user district change is one coordinated navigation action updating shared preference and affected directory scopes while resetting their towns/dealer selections. Returning within an unchanged tab context does not rebuild its filters from defaults. Persisted preference hydration must not overwrite a just-opened deep link.

Justified new dependencies: Zustand for shared client preference, and SDK-compatible AsyncStorage for the non-sensitive preference. No heavy UI library is proposed; reuse Modal, SVG, gesture/safe-area/image tooling already installed. Native connectivity integration will use a small SDK-compatible module only if needed after inspecting the runtime; it is not a reason to introduce a separate networking stack.

Foreground repair stays within the current secure architecture. Preserve stable same-owner UI/drafts during valid-session revalidation while still enforcing token expiry and clearing immediately on revocation/logout/switch. Cold-start offline restoration must not reveal a cached private account. Keep these paths separately tested; do not make “offline friendly” mean unverified private access.
