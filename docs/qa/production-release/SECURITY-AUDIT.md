# Security audit

Audited commit `6e39a9a6af7a6aaa2806e9eaab9481634fb496d2`. Safe, bounded testing against a local
isolated deployment only; nothing was sent to a production host or a real provider.
Scenario-level results: [API-SECURITY.md](API-SECURITY.md), [TENANT-ISOLATION.md](TENANT-ISOLATION.md),
[RBAC-MATRIX.md](RBAC-MATRIX.md), [IDENTITY-MATRIX.md](IDENTITY-MATRIX.md).

## Verdict

**No P0 or P1 security finding.** No authentication bypass, authorization bypass, admin bypass,
cross-tenant data access, privilege escalation, token replay, session confusion between admin
and person sessions, KYC-document exposure or secret leak was found. One P3 dependency-hygiene
item (BUG-108). The out-of-band stale dealer page (BUG-111) shows only public directory data.

## Remaining risks and limits

- **Real providers were not exercised**: MSG91's own expiry, attempt and resend caps
  (AUTH-004/006/007), Google OAuth with a real consent screen, Resend domain authentication,
  R2 bucket policy and CORS. These are in the manual checklist.
- **Default upload-signing secret**: production does not refuse the committed default
  `UPLOAD_SIGNING_SECRET`, but under r2 the only code that uses it (the local stand-ins) is not
  mounted (#241), so it is inert. Worth a production guard as defence in depth.
- **Enquiry state machine**: OWNER/MANAGER can move an enquiry between any statuses (UPD-2);
  authorization holds, but there is no rule to say which moves are invalid.
- Not performed: authenticated DAST crawl, TLS/HSTS/header review of the live domain, cloud IAM
  review, penetration test by a third party, Semgrep run (CI job uses a container this
  environment cannot run).
