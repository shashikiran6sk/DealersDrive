# Native Home and dealers

F103 completes the customer Home and dealer destinations linked from Explore/car details. Existing public config, vehicle discovery, dealer directory/typeahead/profile and dealer inventory APIs are reused without bearer/cookies or backend/schema changes.

Home follows the existing hero, Recently added/SUV/Automatic/Under ₹10 lakh rows and journey/trust/buyer messaging. The approved existing hero asset is copied verbatim and operator-configured hero is respected with a local fallback. Four inventory rows/config load independently in parallel; partial failure leaves search/navigation and other rows usable. Home and Explore share the debounced car search component. Dealer/admin console calls to action are excluded from the customer app, not removed from the website.

Directory uses the same standard conceptual dealership SVG as the website, not an invented yard photograph or logo. Approved portfolio photos appear only on the profile; absence shows the conceptual fallback with a clear caption. Server-composed years/price/available-stock strings and Dealer Verified labels are preserved. The public contact array contains city/GSTIN/hours, not a dealer phone. No phone exposure or new generic dealer enquiry is invented.

Directory/typeahead keep district/town scope and response search echo; inventory fixes the dealership and strips location parameters its strict API rejects. Native inventory filters reuse the same groups except town/dealer, with a separate dealer-scoped preview cache key. Profile/stock load independently; virtualized lists, bounded pages/render batches and non-cancelling next-page requests avoid navigation/request churn. Gallery photo arrays are memoized to preserve selected photo across inventory/search rerenders.

Maps is a user-tapped external Google Maps URL validated by the existing contract. No embedded map, guessed pin/address geocoding, location permission or paid SDK. The native gallery/header/hero use PR #311 branding and existing neutral/Manrope styling. SVG and WebP assets use existing Expo Image support ([official formats](https://docs.expo.dev/versions/latest/sdk/image/)); installed-device quality/insets/keyboard/back validation remains a release gate.
