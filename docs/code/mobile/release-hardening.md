# Android release boundaries

`app.config.ts` delegates to the tested build configuration while retaining app.json's approved branding and blocked permissions. Development/preview IDs differ; production intentionally needs explicit owner-approved identity, version, HTTPS origins and matching App Links host. APP_RELEASE_APPROVED is an accident-prevention input, not permission by itself. `eas.json` pins tooling/profiles without creating a cloud resource or enabling OTA.

`incoming-link.ts` processes untrusted system paths before Expo Router navigation. It bounds length, origin, route, parameters, duplicate keys and encoding, then maps only customer/public destinations. It cannot authorize mutations or accept OAuth/session credentials. Protected screens still verify their owner on the server. Custom paths normalize through the configured website origin, and the native adapter emits a canonical HTTPS URL so React Native and Router retain the path consistently. A regression uses the installed native URL/Router extractor for cold/warm links. Canonical encoding avoids forwarding malformed percent sequences; the remaining framework decoder advisory still needs runtime review.

`app-error-boundary` uses Expo Router's boundary interface but discards raw exception contents, offering generic recovery. `about-screen` displays public version/build metadata and existing policy/support destinations with approved independent brand primitives. No network telemetry or new crash SDK is introduced. Operational monitoring, signature association and real-device checks are [external release gates](../../mobile/release-operations.md).

Native validation CI builds arm64 APK/AAB with generated test signing and reserved invalid HTTPS hosts. `check-android.py` uses a hash-pinned build-only defusedxml parser that refuses DTD/entity processing and validates the actual merged release manifest, minimal permissions and native ELF LOAD alignment; zipalign independently checks ZIP placement. The AndroidX app-private receiver permission is permitted only for the exact package and signature protection. Unused biometric permissions are removed rather than broadly allowlisted. Adversarial fixtures ensure these checks still reject unsafe binaries/configuration. `check-bundle.mjs` inspects Android source-map paths for server, policy-archive and build-tool modules on each JS export; it is not a substitute for binary/secret testing.

Store graphics derive from the unchanged approved SVG masters through the existing build-only Sharp renderer. The DD symbol alone supplies launcher/adaptive/splash/store icon; the feature graphic composes separate approved geometry on white. No recreated lettering, extra branding runtime dependency or web redesign is introduced.

See [validation](../../mobile/f108-validation.md), [security assessment](../../mobile/security-review.md) and [production NO-GO](../../mobile/production-acceptance.md). No self-approval, merge, production activation or publication follows from a green check.

The mobile Turbo task explicitly passes/hashes all public and build-identity inputs used by dynamic Expo configuration. Its strict environment remains enabled; unrelated packages are unchanged. Preview positive/negative builds verify version input propagation without creating a production identity or asserting release approval. CI uses a full AOSP API 36 image for native screenshot smoke after preserving a Google-image System UI ANR failure; it never auto-dismisses ANR dialogs or reports an obstructed run as passed.
