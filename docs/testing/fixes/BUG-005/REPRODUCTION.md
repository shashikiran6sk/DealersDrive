Entry: authenticated dealer POST /vehicles/:id/submit. Cookie resolver reads the current session, user status/seat, workspace membership, dealer status and role. Route permission and ACTIVE guards run before the service transaction. Service requires owned stock, waits for listing FOR UPDATE, checks listing transition/completeness, claims registration and emits the listing audit/outbox in the same transaction. Nothing rechecks the member after the wait. Owner removal separately locks the dealership, changes the preserved member row to REMOVED and records its actor/timestamp; it has no listing lock. Architecture inspected: vehicle create/update/delete/submit/lifecycle/reactivation writes, contracts role permissions, listing locks/state transitions/registration claims/audit/outbox, cookie/dev identity resolvers, session revocation/expiry, workspace choice, member removal/role updates/invitation acceptance, Admin suspension/reinstatement and destructive rejection cascade. Enquiry status writes use a separate resource lock and cached actor permissions; that adjacent path requires an independent controlled reproduction before attribution or a separate correction.

Design before code: add a transaction authorization guard exported through the auth facade. Existing vehicle/listing mutations acquire their current resource lock first, then lock and reread the current dealership, exact membership, user/seat and real session before any privileged mutation. Required permissions come from the fresh role; ACTIVE requirements apply only to lifecycle operations, preserving DRAFT/PENDING draft preparation. Hold authorization rows until commit so a later revocation serializes after an already authorized write. Create has no existing listing resource, so its authorization boundary precedes insert.

Avoid waiting for authorization row locks while holding the resource: dealer rejection holds the dealer and can wait on cascade deletion of that same listing. Shared SKIP LOCKED reads distinguish an absent row from a currently locked row through a nonlocking existence check. A busy authority returns a defined409 with no write instead of waiting into a resource/dealer lock cycle; missing/revoked authority401, lost permission403. Optional absent legacy seats preserve existing semantics, with an exclusive user lock and recheck protecting concurrent seat insertion. This design needs controlled busy-lock and reverse-order tests, not just the original green reproduction.
