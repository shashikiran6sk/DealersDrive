## 3. Production deployment impact

Nothing in this campaign deployed, migrated, published or changed production configuration. After every merge, the release run was build-only: `AWS_DEPLOY_ENABLED` is unset and `deploy-dev` is commented out. Vercel `main` deploys are disabled, and `android.yml` runs on PRs only, with no EAS submit.

**Migrations now on `main`, in order.** All must run before the API that reads them.

1. #279: `20261013120000_dealership_contact_sharing`, `20261013120100_enquiries_sharing_grant_index` (CONCURRENTLY, in its own file), `20261013130000_legal_publication_metadata`, `20261013140000_analytics_privacy_notice`.
2. F100: `20261014090000_native_sessions`. Additive boolean with a default.
3. F106: `20261015100000_support_create_retry`. Nullable columns and a unique index.
4. F107: `20261015110000_customer_deactivation`. Nullable columns. `sessions` is a hot table, so run it with an operator-set `lock_timeout`.

**Deploy order:** run the migrations, then the API, then the web. Native sign-in stays off (`NATIVE_CUSTOMER_AUTH_ENABLED`) and needs the approved legal publication in production. An Android release needs a new native build and is not covered by any deploy here.

**Dependency changes reaching runtime:** F108's `pnpm.overrides` (`postcss`, `qs`, `fast-uri`, `source-map-js`).
